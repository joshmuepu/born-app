# Spike 2 — HEVC and other codecs across hardware

**Question.** Which formats actually play in Born Again's engine, with what quality, and what is the
easiest way for the owner to find out on the church Windows PC?

**How tested** (dev Mac M4 Max, macOS 26.x, Electron 33.4.11 / Chromium 130, 2026-10-15). A runnable
**media compatibility test** (`spikes/media/compat/`) plays 22 test files muted for ~3 s each in a
real window and reports: plays or not, real resolution, duration, dropped frames, time to first frame,
and Chromium's own `MediaCapabilities` answer. Raw result: `results/measured-2026-10-15/compat-darwin-arm64.json`.
Test files were generated by Chromium's recorder and macOS's converter (no FFmpeg), 4 s each.

## Measured on the Mac

| File | Result | Notes |
|---|---|---|
| H.264 720p30 / 1080p30 + AAC / **1080p60** / **4K30**, MP4 | **PASS** all | 0 dropped frames; first frame 20–130 ms; hardware decode |
| **HEVC 1080p30** MP4 · **HEVC 1080p30 in .mov** · **HEVC 4K30** MP4 | **PASS** all | hardware decode; 0 dropped |
| H.264 in **.mov** (QuickTime) | **PASS** | |
| H.264 in **.mkv** (Matroska) | **PASS** | **Correction:** an earlier note in the design package said MKV is "not playable" from `canPlayType`; a *real* file plays |
| VP9 + Opus, VP8, AV1 (WebM) | **PASS** | VP8 is software; AV1 hardware on this chip |
| Vertical (1080×1920) H.264 | **PASS** | plays pillarboxed; app must handle portrait |
| **ProRes 422 .mov** | **FAIL** | `code 4 — no supported streams` |
| Damaged: 0-byte `.mp4` | FAIL | `format error` |
| Damaged: text file named `.mp4` | FAIL | `could not open` |
| **Damaged: truncated `.mp4`** | **PASS (!)** | plays 3.4 s of a 4.0 s clip and stops — **a half-copied file is not caught by "does it play"** |
| Audio-only file named `.mp4` | FAIL (no picture) | detected: 0×0 |
| AAC .m4a, FLAC, WAV, Opus | **PASS** | |

**Two lessons about the test method itself**

1. **`canPlayType()` and `MediaCapabilities` are not reliable gates.** `canPlayType` said "no" for
   MKV and `MediaCapabilities` said "NO" for several files that played perfectly. The only trustworthy
   test is *actually loading and decoding a frame*. The preflight design already says "test-play";
   this makes it a requirement, not a nicety.
2. **A truncated file passes a short play test.** Preflight must also compare *played length* with the
   file's reported length, or check the file size/hash against the one recorded at import.

## Verdict

- **Final for this machine class (Apple-silicon Mac, hardware decode): SAFE** for H.264, HEVC, VP9,
  AV1, MP4/MOV/MKV/WebM containers. **ProRes is not supported — final.**
- **Pending for Windows / the church PC: UNKNOWN.** HEVC on Windows depends on the GPU and (often) a
  Microsoft codec extension *(unverified)*; the same is true for AV1. The owner runs the same test there.

## What it means for the roadmap

1. Phase 1b's supported list (MP4 H.264+AAC) stands. HEVC is **"works on some computers"** — show a
   clear message, never silently accept it.
2. Add **MKV (H.264)** and **MOV (H.264)** to "plays" in the friendly-error table (they do).
3. Preflight: real decode of a frame **and** a length/size check.

## By hand (church Windows PC) — ~2 minutes

1. In the repo: `spikes\media` → run `..\..\node_modules\electron\dist\electron.exe compat` (a window
   opens). *(No `node_modules`? run `npm install` once in the repo folder.)*
2. Press **Run all tests**; wait about a minute.
3. Press **Copy results** and paste the text into a message to me.
4. **Also** drag two or three of the church's *own* videos (a phone video, a sermon export) onto the
   grey box and include those lines.
